# 虚拟案例 02：BP 初筛后建议不再推进

> 本案例为完全虚拟、脱敏后的 workflow 示例，不对应任何真实项目。

## 场景

公司以“行业智能平台”定位融资，但产品同时横跨自动化、客服、仿真和数据服务。材料主要描述定制项目，没有说明共同产品、重复采购或可扩张的交付方式，估值却按高增长平台定价。

## 用户输入

```text
使用 $ai-work-hub-diligence 看这个 BP，不生成文件，直接告诉我判断。
```

## 示例输出

**不投，建议不再推进。**

核心问题是产品逻辑与价格不匹配：目前更像多个定制服务业务的集合，没有形成清晰的标准产品和规模效应。即使按公司提供的收入与订单口径分析，也不足以支持平台型估值。这个判断不依赖公司补齐银行流水或合同。

最有力的反对理由是：公司可能已形成可复用模块，只是 BP 没讲清楚。但目前没有足够信息使它优先于其他机会。

下一步不启动完整尽调。只有以后出现标准产品持续复购、交付效率改善或价格显著变化等实质新信息时，再考虑重看。若推荐方希望解释差异，只需问：不同客户到底复用了什么，收入增长是否仍需要同比增加交付人力？

## 流程要点

- 先读材料，按公司口径分析，也可以得出清晰的不投判断。
- 没有独立核验不等于数据虚假；否定结论应基于实际商业、技术、价格或优先级问题。
- 不为已经建议放弃的项目生成六项审计要求，也不人为设置 48 小时补资料期限。
- 用户说不生成文件，本轮不建档或归档；若已有项目，只有用户明确同意归档后再移动。
