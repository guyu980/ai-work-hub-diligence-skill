# Public And Technical-Team Checks

Run a lightweight public check when identifiable company, product, customer, financing, founder, or technical claims can materially change the view.

For AI and deep-tech projects, research a founder, chief scientist, CTO, research lead, algorithm lead, professor, lab PI, principal engineer, or other core technical leader when first identified. Repeat only when a new high-impact person appears.

Check relevant primary or authoritative sources:

- official company, university, lab, personal, and prior-employer pages;
- papers, patents, Google Scholar, Semantic Scholar, DBLP, arXiv, and conference records;
- GitHub, Hugging Face, model cards, benchmarks, and major open-source contributions;
- public product launches, customer references, talks, and prior operating roles.

Resolve identity carefully across aliases and common names. Evaluate relevance to the company's actual technical route, not prestige alone.

Write a compact assessment into `团队技术背景与可信度` in the running judgment:

```text
- 人员: 已核验背景；与项目路线的关系；待确认事项。
- 对投资判断的影响: 上修 / 中性 / 下修，以及原因。
```

Investigate identity or affiliation conflicts when material. Missing public code, a sparse publication record or an unanswered biography detail alone does not imply weak capability or trigger an IP/employment audit. Judge the technical contribution's relevance to the product; legal documents or reproduction work are not routine background-check requirements.

Create a separate person card in Memory Graph only when the person has reusable industry standing beyond this single project.
